# Methods

## 1. Genome selection and quality control

Complete genome assemblies for six ESKAPE species (*Enterococcus faecium*, *Staphylococcus aureus*, *Klebsiella pneumoniae*, *Acinetobacter baumannii*, *Pseudomonas aeruginosa*, and *Enterobacter cloacae* complex) were retrieved from NCBI RefSeq using the datasets CLI (v18.23.0) with a target of 150 genomes per species. Target sample size was chosen to match the scale of the published *Acinetobacter* cohort (n=132; Muthuraman et al., 2026) and to ensure balanced class representation in multi-class classifiers. For *E. cloacae* complex, accessions were drawn across six constituent taxids with per-member caps to avoid over-representation of any single member species; this complex was treated as a single classifier class throughout, following WHO priority pathogen classification (2024), with internal phylogenetic heterogeneity acknowledged as a pre-registered study limitation. Assembly quality was assessed with CheckM2 v1.0.2; genomes failing completeness <95% or contamination >5% thresholds were excluded. Genomes were additionally screened by multilocus sequence typing (MLST v2.23.0, PubMLST schemes); 22 accessions where MLST-derived species assignment was discordant with the deposited NCBI taxonomy were excluded. The final dataset comprised 878 complete genomes (*A. baumannii* n=150, *E. cloacae* complex n=146, *E. faecium* n=150, *K. pneumoniae* n=132, *P. aeruginosa* n=150, *S. aureus* n=150).

## 2. Defence system prediction and resistance gene annotation

Defence systems were predicted using DefenseFinder v2.0.1, with the AntiDefenseFinder module invoked via the `--antidefensefinder` flag, and PADLOC v2.0.0, applied to all 878 assemblies. The two tools employ partially overlapping but distinct HMM databases; using both maximises recall of the full defence repertoire. A non-redundant union of predictions was constructed: system types detected by only one tool were included once, and system types detected by both tools in the same genome were recorded as a single occurrence to prevent double-counting. CRISPR-Cas systems are detected independently by both tools, and a third dedicated tool was therefore not employed.

ARGs were identified using ResFinder v4.7.2 against the ResFinder database. Integrative and conjugative elements (ICEs) and integrative and mobilisable elements (IMEs) were detected by tBLASTn against the ICEberg2 protein database (threshold: percent identity 40%, query coverage 80%), identifying elements capable of horizontal ARG transfer between genomes. IS elements were detected using ISEScan v1.7.2.3 and annotated to IS family; IS elements act primarily as chromosomal transposition units and their burden reflects genome plasticity rather than directional ARG acquisition.

Acquired metal resistance genes were identified using AMRFinderPlus v4.2.7 (`--plus --organism` flags; database version 2026-03-24.1), retaining only hits with `Subtype == "METAL"`. BacMet2 tBLASTn was evaluated but excluded from analysis, as hits at any identity threshold were dominated by constitutive RND efflux pump homologs, producing a 6-fold Gram-negative/Gram-positive artefact unsuitable for cross-species comparison. A known crash in AMRFinderPlus v4.2.7 on specific HMM domain alignments affected 82 genomes (*S. aureus* 53/150, *E. faecium* 28/150, *A. baumannii* 1/150); these genomes were assigned zero metal resistance genes, representing missing data rather than confirmed absence, and metal resistance analyses for these two species should be interpreted with that caveat.

## 3. Feature matrix construction

For each genome, a feature matrix was assembled comprising binary defence system presence/absence columns (`dp_*`, one per system type across the non-redundant union of DefenseFinder and PADLOC predictions), defence system copy-number columns (`dc_*`), anti-defence system counts, ARG counts, ICE/IME counts, IS element counts, metal resistance gene counts, and genomic context variables (genome size, GC content). The full matrix comprised 878 rows by 631 columns.

For Q1 (species classification), only `dp_*` columns were used as input features. Presence/absence encoding was chosen over copy-number because the question concerns qualitative defence system composition: whether a given defence gate is present in a genome, not how many copies surround it. Copy-number variation reflects local genomic context rather than defence architecture and would dilute the compositional signal. Of the 274 `dp_*` columns, nine were identified as near-exclusive species markers by a per-species prevalence specificity score (standard deviation of per-species prevalence fractions, normalised by 0.5; threshold 0.70) and removed to prevent the classifier from exploiting direct taxonomic signals rather than defence composition. Specificity scores for these nine features ranged from 0.705 to 1.035; five were PADLOC-annotated *K. pneumoniae*-specific system types, two were *P. aeruginosa*-specific, one was *S. aureus*-specific, and one was *E. cloacae* complex-specific (Supplementary Table S2). This left 265 binary features for Q1.

For Q2 (ARG burden prediction), ARG burden was defined per species as a binary label derived from a per-species tertile split of total ARG count. Genomes in the top tertile were labelled high-burden (positive class) and those in the bottom tertile were labelled low-burden (negative class); the middle tertile was excluded to sharpen the contrast between the two classes. The tertile split was computed within each species independently, because baseline ARG counts differ substantially across species owing to genome size and intrinsic resistance diversity; a global split would confound ARG burden with species identity. Input features for Q2 were filtered per-species, retaining only `dp_*` columns present in more than 5% of genomes within that species. The `dp_*` matrix is approximately 97% zeros across all 878 genomes, and rare features contribute no useful signal to within-species models. Gram-positive and Gram-negative bacteria also differ systematically in defence system repertoire, and a global prevalence filter would eliminate Gram-positive-specific systems. Per-species filtering retained between 23 and 85 features depending on species (EC: 68, KP: 85, PA: 74, AB: 30, SA: 27, EF: 23).

## 4. Phylogenetic grouping and cross-validation design

Whole-genome Mash distances were computed for all 878 genomes using k-mer size k=21 and sketch size s=1000 (Mash v2.3). For each genome, Mash retains the 1000 smallest hash values of all 21-mers as a compact sketch; pairwise distance between two sketches is estimated from their Jaccard k-mer similarity and approximates the Average Nucleotide Identity complement. This approach is computationally tractable at 878-genome scale (384,753 pairs, runtime approximately three minutes) without requiring multiple sequence alignment.

Phylogroups were defined by within-species hierarchical clustering of pairwise Mash distances using average linkage. A species-specific distance threshold of t=0.010 was applied for five of the six species; *P. aeruginosa* required a tighter threshold of t=0.005 because clinical PA isolates in this dataset exhibited unusually low within-species diversity (maximum pairwise distance 0.026), and the default threshold merged 104 independently-evolved isolates into a single phylogroup at t=0.010, which would have concentrated an entire CV fold on near-identical isolates. Global clustering across all 878 genomes was evaluated and rejected, as a single threshold collapsed highly clonal species (*S. aureus*, *K. pneumoniae*) into one or two phylogroups each, making a 5-fold GroupedKFold structurally infeasible. Clustering yielded 95 phylogroups across the six species (AB: 13, EC: 22, EF: 7, KP: 18, PA: 26, SA: 9).

Phylogroup assignments were validated against MLST sequence types using PubMLST schemes. Of 109 sequence types represented by two or more genomes, 108 (99.1%) had all members assigned to the same phylogroup, confirming that Mash-derived groups correctly partition clonal lineages. The single discordant sequence type spanned two phylogroups at a borderline Mash distance.

All classifiers from Phase 7 onwards used GroupedStratifiedKFold with 5 folds, grouping on phylogroup assignments. Bacterial genomes from the same clonal lineage share defence system profiles through shared ancestry rather than independent biological processes; standard stratified CV that places clonal genomes across train and test folds inflates performance by testing recognition of ancestry rather than generalisation of defence architecture. Effective sample size for model evaluation is the number of phylogroups (95), not the number of genomes (878).

## 5. Machine learning models and cross-validation

Three supervised classifiers were trained in sequence (Logistic Regression [LR], Random Forest [RF], and XGBoost), representing increasing model complexity. This ordering is deliberate: a more complex model must produce a performance gain that justifies its reduced interpretability. LR was additionally included because its coefficients carry a direct log-odds interpretation per feature; when LR performs competitively, it provides interpretable evidence without requiring post-hoc attribution methods such as SHAP.

A stratified random classifier, predicting class proportions without using any features, was trained as a null baseline. Any supervised model must exceed null performance by a margin large enough to exclude sampling artefact.

For Q1 (species classification), all three classifiers used 265 binary `dp_*` features and the 6-class target (ESKAPE species). LR was fitted with L2 regularisation, one-vs-rest scheme, and regularisation strength C selected by grid search. RF was tuned over n\_estimators (50, 100, 200), max\_depth (10, 20, None), max\_features (sqrt, 0.3), and min\_samples\_leaf (1, 3); best parameters were max\_depth=20, max\_features=sqrt, min\_samples\_leaf=1, n\_estimators=100. XGBoost was tuned with early stopping on a held-out inner validation fold to prevent iteration-driven overfitting.

For Q2 (ARG burden prediction), separate binary classifiers were trained per species using per-species filtered `dp_*` features and the top/bottom tertile ARG burden label. Q2 classifiers were fitted independently for each species; no cross-species pooling was used because baseline ARG burden, feature sets, and class sizes differ across species.

Hyperparameter search for all models used a nested cross-validation structure: the outer loop (GroupedStratifiedKFold, 5 folds, grouped on phylogroup assignments) generated held-out test folds that were never seen during model training or selection; within each outer training split, GridSearchCV applied 3-fold inner cross-validation to select hyperparameters. Test fold data informed neither hyperparameter selection nor model fitting.

Primary performance metric for Q1 was balanced accuracy (mean of per-class recall), chosen because standard accuracy is biased by the uneven discriminability of the six classes; *A. baumannii* IC2 clones occupy an atypically depauperate region of defence feature space and would be down-weighted under accuracy. Primary metric for Q2 was area under the receiver operating characteristic curve (AUROC), chosen because Q2 asks whether defence profiles rank genomes by ARG burden across all decision thresholds, not whether a classifier performs at a fixed cutpoint. AUROC is also insensitive to the class imbalance introduced by excluding the middle tertile.

Bootstrap confidence intervals (95%, 1000 iterations) were computed for all primary performance metrics by resampling across the five outer CV fold scores. Model comparisons (LR vs RF, RF vs XGBoost) used the McNemar test on pooled fold-level predictions; a model was considered to outperform its predecessor only if the performance gain was statistically supported (p < 0.05, Benjamini-Hochberg corrected across comparisons).
